# V3.1 - Data Quality Automation Hardening

## Objective

Improve the reliability of the Sales Data Quality Automation workflow
through issue status tracking and end-to-end testing.

## Improvements

- Added `OPEN` / `RESOLVED` status for data quality issues.
- Added issue history tracking using `Log Key`.
- Prevented resolved issues from being logged again after the source data is fixed.
- Improved handling of empty values and numeric zero.
- Added end-to-end test cases for common data quality scenarios.

## E2E Test Cases

| Transaction ID | Scenario | Expected Result |
|---|---|---|
| TRX-1200 | Quantity is empty | Missing Quantity |
| TRX-1201 | Unit Price is empty | Missing Unit Price |
| TRX-1202 | Quantity = 0 | Quantity must be greater than 0 |
| TRX-1203 | Valid transaction | PASS |
| TRX-1204 | Quantity = abc | Invalid Quantity |

## Resolution Test

TRX-1187 was initially detected with:

`Missing Date`

After the source data was corrected, the transaction passed
the quality check and was not logged as a new issue.

The previous issue remained:

`TRX-1187 | Missing Date | RESOLVED`

This confirms that resolved issues are preserved as history
without being duplicated during subsequent workflow runs.

## Result

V3.1 successfully passed end-to-end validation.

The workflow can now:

1. Detect data quality issues.
2. Classify valid and invalid records.
3. Log review issues.
4. Track issue status.
5. Preserve resolved issue history.
6. Avoid re-logging resolved issues.
